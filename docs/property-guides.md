# Property usage guides

Each property has one optional guide with a title and either plain text or one
PDF. Existing guides default to TEXT; other properties are unaffected. The same
published guide is available through valid shared guest QR and personal stay
links. Staff QR and receipt tokens do not grant guest guide access.

## Database and deployment

`20261113020000_add_property_guide_pdf` adds PropertyGuideType (TEXT/PDF), a TEXT
default and four nullable PDF metadata columns. It was generated by Prisma from
the previous and updated datamodels, without connecting to the user's database.
With explicit user authorization on 2026-11-13, `npx prisma migrate dev` applied
this migration to the local development database after a readable backup and
regenerated Prisma Client. Migration status is up to date; existing guide values
were verified unchanged and default to TEXT. No real PDF was uploaded, and AWS
configuration and production remain untouched.

Other development checkouts apply the migration with `npx prisma migrate dev`.
Production uses the existing deployment/migration process (`prisma migrate
deploy`), never migrate dev. No backfill is needed.

PDFs use the existing AWS_REGION / S3_BUCKET_NAME and EC2 role, but a **new private
`guides/*` prefix**. Before production PDF uploads, add narrowly scoped
`s3:PutObject`, `s3:GetObject`, and `s3:DeleteObject` permissions to that prefix in
the configured bucket. Existing permissions restricted to photos/* and imports/*
do not cover guides/*. Keep Block Public Access on; do not add a public-read
policy, ACL or S3 CORS requirement. This implementation makes no AWS changes.

## Administrator contract

All routes require the existing ADMIN Bearer token and a UUID-v4 property ID.
Query parameters are forbidden except optional integer `version` on PDF reads.

- `GET /admin/properties/:id/guide`: `{ property, guide }`, guide null before first save.
- `POST /admin/properties/:id/guide`: existing JSON text save, HTTP 200.
- `POST /admin/properties/:id/guide/pdf`: multipart PDF save, HTTP 200.
- `GET /admin/properties/:id/guide/pdf?version=N`: current saved PDF bytes, including unpublished guides.

Guide shape:

```ts
{
  title: string;
  content: string;
  type: 'TEXT' | 'PDF';
  pdf: { filename: string; sizeBytes: number } | null;
  isPublished: boolean;
  version: number;
  updatedByUserId: string;
  createdAt: string;
  updatedAt: string;
}
```

Storage bucket and object key are never returned. Text saves still require
expectedVersion, title, nonempty content, isPublished. Optional `type: 'TEXT'` is
accepted for compatibility; omitting it also saves TEXT. A successful text save
removes any PDF association. The retired PDF is deleted only after commit.

PDF multipart fields are `expectedVersion`, `title`, `isPublished` (literal
`true` or `false`), optional `content`, and optional `file`. The first PDF save
and replacement require a file. No file means **retain the currently stored PDF**;
this is allowed only if the saved guide is already PDF. No arbitrary storage key
or file ID is accepted. Optional content preserves unsaved text (empty allowed);
omitting it preserves previously saved text, or uses empty string on first save.
Switching to PDF does not expose the retained text to guests. A local file preview
before Save uses a browser object URL, with no server upload until confirmation.

Title: trimmed, 1–100 Unicode characters, no newline or NUL. Text: trimmed,
CRLF/CR normalized to LF, at most 20,000 characters, no NUL. expectedVersion is
0 only on first save and current version thereafter. Version and active admin
are rechecked inside a serializable transaction. A stale save returns
409 PROPERTY_GUIDE_CHANGED; every successful save increments version, including
publication changes. After a lost response, reload before retrying.

Inactive properties may be prepared by admins; guest access remains blocked.
There is one saved guide, no separate draft/published copies and no guide archive.
Saving while published immediately replaces what guests can read. Unpublishing
retains the file for administrators and hides guide JSON and bytes from guests.

## PDF validation and storage

Only one .pdf file up to 10 MiB (10 × 1024 × 1024 bytes), 1–200 pages is accepted.
The MIME type and PDF header/trailer are checked, then pdf-lib parses the document
in a worker with an 8-second deadline and bounded JS heap. Encrypted PDFs,
attachments, JavaScript, launch/remote-file/form-submit actions, interactive
forms, rich media and unsupported URL schemes are rejected. Normal HTTP(S) and
mailto links and internal document navigation are allowed. These structural
checks are **not antivirus scanning**; trusted admins choose the guide content.
The source file is not rewritten or stripped. File names are normalized, stripped
of path/control characters, bounded, and safely encoded for download.

Parsing/upload concurrency is two per process; upload requests are limited to
10/minute/IP/process. Authentication guards run before multipart processing.
S3 keys are server-generated `guides/<property UUID>/<random UUID>.pdf`, with no
user path input. Objects remain private and are never served via public URLs or
presigned download links. Storage errors are generic and do not reveal keys.

Failed uploads and definitively rejected saves attempt safe cleanup. Unknown
transaction/transport outcomes retain the uploaded object for reconciliation,
because a lost response is not proof of rollback. Replacements preserve the old
file until commit and check it is no longer current before deletion. Cleanup
failure does not turn a successful save into a failure. A warning logs only the
server-generated object key for operator reconciliation; there is **no automatic
orphan cleanup job**. Operators must confirm that the key is not referenced by
PropertyGuide before deleting it. No file contents or bearer tokens are logged.

## Guest contract

- `GET /guest/property-guides/qr`
- `GET /guest/property-guides/stay`
- `GET /guest/property-guides/qr/pdf?version=N`
- `GET /guest/property-guides/stay/pdf?version=N`

Each route accepts only its designated guest Bearer token, never a token in the
query string or caller-supplied property/stay ID. QR rotation, inactive property,
private-link expiry/revocation/cancellation and stay revision mismatches use the
existing resolvers. Authorization and the published-guide lookup share a
RepeatableRead transaction.

Guest JSON is `{ property: { id, name, region }, guide }`. Published guide fields
are title/content/type/pdf/version/updatedAt. PDF content is an empty string,
so dormant text is not disclosed. Unpublished/missing guides return guide:null.
PDF bytes require a currently published PDF; missing, unpublished and text-only
guides all return 404 PROPERTY_GUIDE_PDF_NOT_FOUND. An optional version mismatch
returns 409 PROPERTY_GUIDE_CHANGED so the client can reload displayed metadata.

PDF responses are application/pdf attachments with safe Unicode Content-Disposition,
private/no-store, nosniff and no-referrer. The frontend fetches with authorization,
then opens/downloads the Blob; there is no public S3 redirect. Bytes reads are
20/minute/IP/process. Revocation/unpublish affects future requests; an already
downloaded file cannot be revoked or recalled.

Guide content is shared within the property's guest access, not reservation-
specific password access. The client's current fixed entry code and Wi-Fi details
may remain in its supplied guide by agreement. Before switching that property to
per-reservation codes, the owner must replace the PDF without the fixed door code;
reservation passwords remain in the separate personal-link password flow.

Render text as escaped text, not HTML or executable Markdown. PDF availability
does not record guest acceptance or a historical snapshot. Required save
confirmation and publication controls remain in the client.
